## この手順書でできるようになること

Mac のターミナルから、**marketik.jp のブログ記事を「下書き」として投稿できる**ようになります。

```
記事を書く  →  コマンド1つで下書き投稿  →  山崎が確認して公開
```

Claude Code（AIのコーディング補助ツール）と組み合わせることで、記事の執筆・推敲・投稿までを1箇所で完結できます。

**公開ボタンは押せません。** これは不具合ではなく、意図的な設計です（後述）。

## ⚠️ 先に読んでください：5つのルール

セットアップを始める前に、ここだけは目を通してください。
**技術的な難しさより、こちらの方が重要です。**

### ルール1：アプリケーションパスワードは誰にも渡さない

これから発行する「アプリケーションパスワード」は、**あなたのWordPressアカウントの合鍵**です。

- 山崎にも共有不要です（発行はあなた自身が行います）
- **AIのチャット欄に貼らないでください。** Claude Code / ChatGPT / どれもです
- Slack・メール・メモアプリにも残さないでください
- 必要になったら、古いものを取り消して新しく発行すれば済みます

### ルール2：記事の公開は山崎が行う

あなたのWordPress権限は **「寄稿者」** です。記事の作成と下書き保存はできますが、**公開はできません。**

これは信用の問題ではありません。
**「スクリプトの不具合やAIの誤動作があっても、勝手に公開されることはない」**という安全装置です。
人間が必ず1回目を通す仕組みにしてあります。

### ルール3：日本国内から接続する

エックスサーバーの「国外アクセス制限」をONにしています。
**VPNを使っていると接続できません。** うまくいかないときは、まずVPNを切ってください。

### ルール4：本番のテーマファイルは触らない

WordPress管理画面の `外観 → テーマファイルエディター` は、**1文字間違えるとサイト全体が真っ白になります。**
実際、先日 `archive.php` の不具合でメンバーページがサーバーエラーになっていました。

直したい箇所を見つけたら、**編集せず山崎に連絡してください。**

### ルール5：取引先の社名を許可なく書かない

記事に実在のクライアント名を出す場合は、必ず事前に許諾を取ります。判断に迷ったら山崎に確認してください。

## Part 1：Claude Code をインストールする

### STEP 1-1. ターミナルを開く

`⌘ + スペース` → `ターミナル` と入力 → `Enter`

黒い（または白い）画面が出ればOKです。以降、コードブロックの内容は
**この画面に貼り付けて `Enter`** を押します。

### STEP 1-2. インストール

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

数十秒待ちます。終わったら**一度ターミナルを閉じて、開き直してください。**
（インストール先の場所をターミナルに覚えさせるため）

### STEP 1-3. 入ったか確認

```bash
claude --version
```

`2.x.x (Claude Code)` のようにバージョン番号が出ればOKです。

> **`command not found: claude` と出たら**
> ターミナルを開き直していない可能性が高いです。閉じてもう一度開いてから、再度実行してください。
> それでもダメなら山崎に連絡してください。

### STEP 1-4. ログイン

```bash
claude
```

ブラウザが開くので、案内に従ってログインします。
ログインできたら、`/exit` と入力するか `Ctrl + D` を2回押して一度抜けます。

### STEP 1-5. Python が入っているか確認

```bash
python3 --version
```

`Python 3.x.x` と出ればOKです。

> **出なかったら**次を実行してください（初回のみ、数分かかります）。
> ```bash
> xcode-select --install
> ```

## Part 2：WordPress の準備

### STEP 2-1. ログイン

```
https://marketik.jp/wp-admin/
```

山崎が作成したアカウントのメールに、パスワード設定のリンクが届いています。
まだ届いていなければ山崎に連絡してください。

> 💡 ログイン画面が出ずエラーになる場合は、VPNが有効になっていないか確認してください。

### STEP 2-2. 自分の権限を確認する

ログイン後、左メニューの見え方で権限が分かります。

| 見えるもの | 判定 |
|---|---|
| 「投稿」「メディア」「プロフィール」だけ | ✅ 寄稿者。正しい状態です |
| 「プラグイン」「外観」「設定」も見える | ⚠️ 権限が強すぎます。**山崎に連絡してください** |

### STEP 2-3. アプリケーションパスワードを発行する

```
右上の自分の名前にカーソルを合わせる → 「プロフィールを編集」
```

ページの**一番下までスクロール**すると「アプリケーションパスワード」という欄があります。

```
新しいアプリケーションパスワード名: claude-code-takahashi-keigo
　　　　　　　　　　↓
「新しいアプリケーションパスワードを追加」をクリック
```

すると、こんな文字列が表示されます。

```
abcd EFGH ijkl MNOP qrst UVWX
```

### 🔴 ここが最重要ポイント

この文字列は **この1回しか表示されません。** 画面を閉じると二度と見られません。

1. **半角スペースも含めて**すべてコピーしてください
2. **スクリーンショットを撮らないでください**（写真アプリやクラウドに残ります）
3. **誰にも送らないでください**（山崎にもAIにも）
4. 次のSTEPですぐ使うので、**この画面は開いたままにしてください**

万が一失くしても大丈夫です。同じ画面で古いものを「取り消し」して、新しく発行し直せば済みます。

## Part 3：接続設定をする

### STEP 3-1. 作業フォルダと設定ファイルを作る

ターミナルに次をまとめて貼り付けて `Enter`：

```bash
mkdir -p ~/marketik-blog
touch ~/.marketik-wp
chmod 600 ~/.marketik-wp
open -e ~/.marketik-wp
```

`chmod 600` は「**このMacの自分以外は読めない**」という設定です。先に権限を絞ってから中身を書きます。

### STEP 3-2. 設定ファイルに書き込む

テキストエディットが開くので、次の3行を書きます。

```
WP_URL=https://marketik.jp
WP_USER=takahashi-keigo
WP_APP_PASSWORD=abcd EFGH ijkl MNOP qrst UVWX
```

- 3行目は、**さきほどコピーしたパスワードに置き換えて**ください
- **スペースはそのまま**で構いません。引用符（`"` や `'`）は付けないでください
- 書けたら `⌘ + S` で保存し、テキストエディットを閉じます

> 💡 **なぜコマンドで直接書かないのか**
> ターミナルに入力した文字は履歴ファイルに残ります。パスワードを履歴に残さないため、
> わざわざエディタ経由にしています。

### STEP 3-3. 権限を確認する

```bash
ls -l ~/.marketik-wp
```

```
-rw-------  1 （Macのアカウント名）  staff  ...  /Users/（Macのアカウント名）/.marketik-wp
```

先頭が **`-rw-------`** になっていればOKです。
`-rw-r--r--` のように後ろに `r` が付いていたら、もう一度 `chmod 600 ~/.marketik-wp` を実行してください。

### STEP 3-4. スクリプトを置く

山崎から受け取った `wp-draft.py` を、`書類` フォルダなどに保存してから：

```bash
mv ~/Downloads/wp-draft.py ~/marketik-blog/
```

（ダウンロードフォルダ以外に保存した場合は、そのパスに読み替えてください）

置けたか確認：

```bash
ls ~/marketik-blog/
```

`wp-draft.py` と表示されればOKです。

### STEP 3-5. 設定ファイルをAIから隠す

Claude Code があなたのパスワードファイルを読まないように、明示的にブロックします。

一番簡単な方法は、Claude Code 自身にやらせることです。

```bash
cd ~/marketik-blog
claude
```

起動したら、次をそのまま入力してください。

```
~/.claude/settings.json に permissions.deny を追加して、
Read(~/.marketik-wp) を拒否するようにしてください。
既存の設定がある場合は壊さずに追記してください。
```

確認を求められたら承認します。終わったら `/exit` で抜けます。

<details>
<summary>手動でやりたい場合（クリックで展開）</summary>

`~/.claude/settings.json` を開き、次を追記します。**ファイルが既にある場合は上書きせず、`permissions` の項目だけ足してください。**

```json
{
  "permissions": {
    "deny": [
      "Read(~/.marketik-wp)"
    ]
  }
}
```
</details>

```

**ここまで出れば完了です。** 記事は1本も作られていません。

### エラーが出たら

| 表示されたもの | 原因 | 対処 |
|---|---|---|
| `WordPressが 401 を返しました` | ユーザー名かパスワードが違う | `~/.marketik-wp` の `WP_USER` の綴り、パスワードのコピー漏れ（先頭・末尾の欠け）を確認 |
| `WordPressが 403 を返しました` | 海外IP / VPN経由、または権限不足 | **VPNを切る。** それでも出るなら山崎に連絡 |
| `接続できません` | ネットワーク | Wi-Fiを確認。社内ネットワーク以外でも試す |
| `WP_URL が設定されていません` | 設定ファイルが読めていない | `cat ~/.marketik-wp` で3行あるか確認 |
| `WP_URL が http:// になっています` | URLの打ち間違い | `https://marketik.jp` に直す |
| `command not found: python3` | Pythonが無い | `xcode-select --install` を実行 |
| **`権限: 管理者` と出た** | 権限が強すぎる | **すぐ山崎に連絡。** パスワードを取り消して作り直します |

## Part 5：日々の使い方

### 記事ファイルの書き方

`~/marketik-blog/` の中に `.md` ファイルを作ります。書式はこうです。

```
---
title: 記事のタイトル
slug: youtube-algorithm-2026
category: ノウハウ
---
<p>本文の段落。</p>

<h2>見出し</h2>

<p>段落。<strong>強調</strong>もできます。</p>

<ul>
<li>箇条書き</li>
<li>箇条書き</li>
</ul>
```

#### メタ情報の3つのルール

| 項目 | ルール |
|---|---|
| `title` | 日本語でOK |
| `slug` | **半角英小文字・数字・ハイフンのみ。日本語は不可**（URLになるため） |
| `category` | `ニュース` / `ノウハウ` / `実績・事例` のいずれかと**完全一致** |

> `slug` に使えない語：`blog` `service` `contact` `works` `member` `privacy-policy`
> `thanks` `category` `tag` `author` `page` `feed` `wp-admin`、および数字だけのもの
>
> これらは既存ページとURLが衝突します。スクリプトが自動で弾くので、
> エラーが出たら別の名前にしてください。

#### 本文で使うHTML

`<p>` `<h2>` `<h3>` `<ul><li>` `<strong>` `<a>` だけで足ります。
**`<h1>` は使わないでください**（タイトルが `<h1>` になるため重複します）。

### 下書きを投稿する

```bash
python3 ~/marketik-blog/wp-draft.py ~/marketik-blog/記事のファイル名.md
```

成功すると編集画面のURLが表示されます。

```
下書きを作成しました。
  タイトル : ...
  状態     : draft
  公開後URL: https://marketik.jp/youtube-algorithm-2026/
  編集画面 : https://marketik.jp/wp-admin/post.php?post=123&action=edit
```

### 投稿したあと

1. 表示された「編集画面」のURLを開いて、**表示崩れがないか自分で確認**
2. 問題なければ**山崎に連絡**（記事タイトルと編集画面URLを添えて）
3. 山崎が内容を確認し、アイキャッチ画像とメタディスクリプションを設定して公開

### Claude Code を執筆に使う

```bash
cd ~/marketik-blog
claude
```

起動したら、普通の日本語で頼めます。

```
YouTube運用の初心者向け記事を書きたい。構成案を3パターン出して。
```

```
この記事の誤字脱字と、同じ語尾が連続しているところを直して。
```

```
この記事を wp-draft.py の形式（frontmatter + HTML）に変換して。
slug は英語で付けて。
```

> ⚠️ **AIが書いた内容は必ず自分で事実確認してください。**
> 特に**数値・日付・サービス名・アルゴリズムの仕様**は、AIが自信満々に間違えます。
> SNS運用の会社がSNSの情報を間違えるのは致命傷になります。
> 公式発表のURLを確認できない情報は、記事に書かないでください。

## Part 6：やってはいけないこと

| # | 禁止事項 | 理由 |
|---|---|---|
| 1 | アプリケーションパスワードを人やAIに渡す | アカウントの合鍵そのもの |
| 2 | `~/.marketik-wp` をGitにコミットする／Slackに貼る | 同上。公開リポジトリだと即座に悪用される |
| 3 | `外観 → テーマファイルエディター` でファイルを編集する | 1文字のミスでサイト全体が停止する |
| 4 | サーバーパネルのセキュリティ設定を変える | 「国外アクセス制限」をOFFにすると攻撃対象になる |
| 5 | スクリプトの `status="draft"` を書き換える | 公開前チェックを飛ばす動きになる（権限的にも通りません） |
| 6 | 取引先の社名を許諾なく記事に書く | 契約違反になり得る |
| 7 | AIの出力を検証せず投稿する | 誤情報の発信は会社の信用に直結する |

## 付録：この仕組みの安全設計

「なぜこんなに制限が多いのか」を理解しておくと、判断に迷ったときの助けになります。

| 安全装置 | 何を防ぐか |
|---|---|
| WordPress権限を**寄稿者**に限定 | スクリプトやAIが暴走しても、勝手に公開されない |
| スクリプトの `status` を **`draft` に固定** | 上と合わせて**二重**の歯止め |
| エックスサーバーの**国外アクセス制限をON** | 海外からの総当たり攻撃を遮断 |
| アプリケーションパスワードを**人ごとに発行** | 漏れたとき、その1本だけ取り消せば済む |
| 設定ファイルを **`chmod 600`** | 同じMacの他ユーザーから読めない |
| Claude Code に **`Read` 拒否ルール** | AIが誤ってパスワードを読み上げない |
| **人間が必ず最後に公開判断** | 誤情報・許諾漏れを止める最後の砦 |

どれか1つが破られても、他が効くようにしてあります。
**「面倒だから1つ外す」が一番危険**なので、疑問があれば外す前に相談してください。
